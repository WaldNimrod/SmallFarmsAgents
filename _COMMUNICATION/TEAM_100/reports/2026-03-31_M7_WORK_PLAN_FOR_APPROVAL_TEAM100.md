## 3. Scope

### In scope (M7 Phase A — implementation)

1. **Host validation** — automated tests **U01–U12** (and documented **U08** cache behaviour) per [`MANDATE_UPRESS_VALIDATION.md`](../../TEAM_10/MANDATE_UPRESS_VALIDATION.md) and [`docs/UPRESS_VALIDATION_PLAN_HE.md`](../../../docs/UPRESS_VALIDATION_PLAN_HE.md), adapted where the **live `manifest.json` schema** differs from the mandate’s illustrative JSON (see §8).
2. **FTPS upload** — configurable module (env-driven), callable after local `PublishEngine` success; retries and structured logging; **no secrets in repo**.
3. **Publish contract** — clarify and implement one of:
   - **Option A (recommended):** **versioned** `public_report-{ts}.json` / `.html` (and optional `public_report_body-{ts}.html` for WP) + **`manifest.json`** that points to the **latest** artifact names (or URLs relative to uploads base); **atomic update** order documented (artifacts first, manifest last).
   - **Option B:** keep **fixed filenames** only + document CDN/cache risk; still upload `manifest_last_good.json` on success only.
   Team 100 should pick **A or B** (recommendation: **A** for cache + audit trail).
4. **`manifest_last_good.json`** — updated **only** on successful full publish + upload; consumers documented.
5. **WordPress integration (no iframe)** — per [`documentation/05-admin-and-operations/WORDPRESS_PUBLIC_PUBLISH_RUNBOOK.md`](../../../documentation/05-admin-and-operations/WORDPRESS_PUBLIC_PUBLISH_RUNBOOK.md):
   - **v1:** landing page + link to standalone `public_report.html` (already allowed).
   - **M7 target:** **`public_report_body.html`** (or equivalent) generated by publisher + **minimal** WP plugin or child-theme **shortcode** that outputs trusted static HTML from uploads (PHP `readfile` / allowed path only).
6. **Operational wiring** — extend scheduler / runner or documented cron step: `… → publish → ftps_upload` (exact hook to be chosen in implementation; must be idempotent-safe).
7. **Documentation** — `.env.example` keys, runbook updates, Team 10 completion report for G7.

### In scope (M7 Phase B — QA)

Per [`ROADMAP.md`](../../ROADMAP.md) G7: pytest uPress suite, integration FTPS, E2E pipeline, fallback test, WordPress render check, stale banner checks, **3 consecutive** unattended runs, **Nimrod LIVE sign-off**.

### Explicitly out of scope (unless Team 100 expands)

- Public REST API on WordPress.
- Writing to WordPress DB from the agent.
- iframe-based embedding (rejected UX).
- GitHub Actions as **primary** publisher (optional secondary; not required for G7).

## 6. Risks and mitigations

| Risk | Mitigation |
|------|------------|
| FTPS or path blocked | U01–U03 fail fast; uPress support ticket template in validation plan |
| CDN stale content | Versioned filenames (§3 Option A); manifest last points to new names |
| Manifest schema drift vs mandate examples | §8 alignment + single **English** contract doc under `documentation/` |
| WP cannot run custom PHP | Fallback: landing-page-only (link to static HTML) until plugin allowed |
| Secrets leakage | `.env` only; CI skips live tests; grep audit in PR |

## 8. Manifest / artifact contract note (for alignment)

The **live** `manifest.json` today includes: `last_published_at`, `report_date`, `product_count`, `staleness_level`, `community_sources`, rolling window fields, `data_quality`.  
The **mandate’s** illustrative `TEST_MANIFEST` uses different keys (`json_path`, `html_path`, etc.). M7 implementation must either:

- **Extend** the real manifest with backward-compatible optional fields for WP, **or**
- **Document** that WP uses only fixed URLs and versioned files are for humans/CDN only.

**Team 100 should confirm** the preferred consumer contract.
