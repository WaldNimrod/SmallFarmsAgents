### 6.2 FTPS Upload Module Specification

**File:** `organic_market_agent/publisher/ftps_upload.py`

**Transport:** FTPS (FTP over TLS) via `ftplib.FTP_TLS` on port 21.
**CONFIRMED:** SSH/SFTP (port 22) is blocked on uPress. FTPS works with TLS session reuse.
**CRITICAL:** Standard `FTP_TLS` fails with `425 Unable to build data connection`. A subclass that reuses the TLS session on data connections is REQUIRED (see implementation below).

**Interface:**

```python
from dataclasses import dataclass
from pathlib import Path

@dataclass
class FtpsUploadResult:
    success: bool
    files_uploaded: list[str]
    files_failed: list[str]
    remote_base: str
    error: str | None = None

class ReusedSessionFTP_TLS(ftplib.FTP_TLS):
    """FTP_TLS subclass that reuses the control TLS session for data connections.
    Required for uPress — standard FTP_TLS gets 425 errors without this."""
    def ntransfercmd(self, cmd, rest=None):
        conn, size = ftplib.FTP.ntransfercmd(self, cmd, rest)
        if self._prot_p:
            conn = self.context.wrap_socket(
                conn, server_hostname=self.host,
                session=self.sock.session
            )
        return conn, size

def upload_artifacts(
    local_dir: Path,
    file_names: list[str],
    *,
    dry_run: bool = False,
) -> FtpsUploadResult:
    """Upload listed files from local_dir to remote UPRESS_UPLOAD_PATH via FTPS.

    Reads credentials from environment:
      UPRESS_SFTP_HOST, UPRESS_SFTP_PORT (default 21),
      UPRESS_SFTP_USER, UPRESS_SFTP_PASS, UPRESS_UPLOAD_PATH

    Upload order: caller is responsible for ordering files
    (artifacts first, manifest last — see §6.3 upload protocol).

    Raises EnvironmentError if required env vars are missing.
    Returns FtpsUploadResult — never raises on FTP errors (logs + returns).
    """
```

**Implementation rules:**
- Use `ReusedSessionFTP_TLS` (see above) — NOT plain `FTP_TLS`
- Call `ftp.prot_p()` after login for encrypted data channel
- Call `ftp.set_pasv(True)` for passive mode
- **Retry:** 3 attempts per file, exponential backoff (5s, 10s, 20s)
- **Timeout:** 15 seconds for connection, 60 seconds per file upload
- **Connection:** open one FTP session per upload cycle — reuse for all files
- **Remote directory:** `UPRESS_UPLOAD_PATH` is relative to FTP root (which IS WordPress root — no `public_html/`). Confirmed: `wp-content/uploads/market/`
- **Directory creation:** `market/` already created. Module should still `mkd()` with IOError catch for idempotency.
- Log every file upload (success/fail) via `persist_log()` with module `publisher.ftps_upload`
- On failure of any file: continue remaining files, then return partial result
- **No secrets in code** — all credentials from `os.getenv()`
- Close FTP connection in `finally` block (call `ftp.quit()`)

**New alert tags** (add to `utils/pipeline_alert_tags.py`):

```python
TAG_FTPS_UPLOAD_SUCCESS = "[FTPS_UPLOAD_OK]"
TAG_FTPS_UPLOAD_FAILURE = "[FTPS_UPLOAD_FAIL]"
TAG_FTPS_UPLOAD_PARTIAL = "[FTPS_UPLOAD_PARTIAL]"
```

### 6.3 Manifest v2 Schema and Upload Protocol

**The current manifest.json fields are PRESERVED (backward compatible).** New fields are ADDED.

**Manifest v2 schema (complete):**

```json
{
  "schema_version": "2.0",
  "artifact_version": "20260401_060000",
  "last_published_at": "2026-04-01T06:00:00+00:00",
  "report_date": "2026-04-01",
  "product_count": 12,
  "staleness_level": "current",
  "staleness_days": 0,
  "community_sources": 5,
  "index_window_days": 7,
  "window_start_date": "2026-03-26",
  "window_end_date": "2026-04-01",
  "distinct_community_sources_in_window": 5,
  "data_quality": { "...existing structure..." },

  "artifacts": {
    "json": "public_report-20260401_060000.json",
    "html": "public_report-20260401_060000.html",
    "body_fragment": "public_report_body-20260401_060000.html"
  },
  "fixed_names": {
    "json": "public_report.json",
    "html": "public_report.html",
    "body_fragment": "public_report_body.html"
  },
  "upload_base": "wp-content/uploads/market/"
}
```

**Field definitions:**
- `schema_version`: `"2.0"` (was absent in v1 — add now)
- `artifact_version`: UTC timestamp `YYYYMMDD_HHMMSS` of generation
- `staleness_days`: integer days since `report_date` — new field for WP consumers
- `artifacts`: versioned filenames (cache-safe, immutable)
- `fixed_names`: fixed filenames (always overwritten, for simple consumers)
- `upload_base`: remote directory path for URL construction
- All existing fields remain unchanged for backward compatibility

**`manifest_last_good.json`:** identical to `manifest.json` but only written/uploaded on FULL success (all files uploaded, no errors). WordPress should prefer `manifest_last_good.json` when `manifest.json` is missing or corrupt.

**Upload protocol (strict order):**

```
1. Upload versioned JSON:     public_report-{ts}.json
2. Upload versioned HTML:     public_report-{ts}.html
3. Upload versioned body:     public_report_body-{ts}.html
4. Upload fixed JSON:         public_report.json          (overwrite)
5. Upload fixed HTML:         public_report.html          (overwrite)
6. Upload fixed body:         public_report_body.html     (overwrite)
7. Upload manifest.json       (LAST — points to new versions)
8. IF steps 1–7 all succeeded:
     Upload manifest_last_good.json  (copy of manifest.json)
```

**If any step 1–6 fails:** STOP. Do NOT upload `manifest.json`. Log alert with `TAG_FTPS_UPLOAD_PARTIAL`. The old `manifest.json` on the server still points to the previous valid set.

**If step 7 fails:** Log alert. Old manifest remains. `manifest_last_good.json` is untouched.

### 6.5 WordPress Body Fragment and Shortcode Specification

**Body fragment (`public_report_body.html`):**

- Contains ONLY the inner content that goes between `<body>` and `</body>` in the current `public_report.html`
- Includes embedded `<style>` block (same CSS from the full template, minus the `body` reset — WordPress theme provides that)
- Includes: report meta bar, stale banner (conditional), data quality box, price table, footer note
- Does NOT include: `<!DOCTYPE>`, `<html>`, `<head>`, `<body>` tags, Google Fonts link (WordPress theme should load Heebo, or the fragment includes a font-face fallback)
- Generated by `PublishEngine` using a separate Jinja2 template: `organic_market_agent/publisher/templates/public_report_body.html`
- RTL is handled by wrapping in `<div dir="rtl" lang="he" class="sf-market-wrap">`
- All CSS classes are prefixed with `sf-` to avoid WordPress theme conflicts

**WordPress shortcode — install in ACTIVE CHILD THEME:**

Nimrod confirmed the site has an active child theme. The shortcode goes into the child theme's `functions.php`.

**PHP code** (also saved as `tools/wordpress/organic-market-shortcode.php` for reference):

```php
<?php
/**
 * OrganicMarketAgent — shortcode to embed the price report body fragment.
 *
 * Usage: [organic_market_report]
 * Reads: wp-content/uploads/market/public_report_body.html
 * Requires: file must exist and be readable
 */
function sf_organic_market_report_shortcode($atts) {
    $base = wp_upload_dir()['basedir'] . '/market';
    $file = $base . '/public_report_body.html';
    if (!file_exists($file)) {
        return '<p style="color:red;">Market report not available.</p>';
    }
    return file_get_contents($file);
}
add_shortcode('organic_market_report', 'sf_organic_market_report_shortcode');
```

4. The fragment is auto-updated by the FTPS upload pipeline — no further WP action needed
5. Alternative: if child theme `functions.php` modification is not desired, place the PHP file in `wp-content/mu-plugins/organic-market-shortcode.php` as a must-use plugin

### 6.7 Rollback and Degradation Handling

| Scenario | Behavior |
|----------|----------|
| FTPS upload fails completely | Local pipeline succeeds; alert `TAG_FTPS_UPLOAD_FAILURE`; old artifacts remain on server; `manifest_last_good.json` is untouched |
| FTPS upload partially fails | Stop upload sequence; alert `TAG_FTPS_UPLOAD_PARTIAL`; old `manifest.json` still points to previous valid set |
| uPress temporarily unreachable | Upload retries 3x; if all fail → same as "fails completely" |
| Local publish fails (`PublishAbortError`) | No upload attempted; existing pipeline behavior (alert + log) |

**WordPress degradation:**
- If `manifest.json` is corrupt/missing, WP shortcode falls back to reading `public_report_body.html` directly (fixed filename always overwritten)
- If `public_report_body.html` is missing, shortcode shows "not available" message
- If all files are stale (>8 days), the stale banner in the fragment itself warns users

## 8. Manifest / Artifact Contract Alignment

**Problem:** The current `PublishEngine` manifest and the mandate's illustrative `TEST_MANIFEST` use different field names.

**Resolution:** The manifest v2 schema (§6.3) is the authoritative contract. It:
- Preserves ALL existing fields from `PublishEngine` (no breaking change)
- Adds versioned artifact pointers in an `artifacts` sub-object
- Adds `schema_version` for forward compatibility
- Does NOT use the mandate's `json_path`/`html_path` flat fields (superseded by `artifacts.json`/`artifacts.html`)

**The mandate's test code** (`TEST_MANIFEST` in `MANDATE_UPRESS_VALIDATION.md`) is illustrative only. M7 tests must validate against the v2 schema defined in §6.3 of this document.
