## 3. Acceptance criteria (numbered, testable)

### Item 1 — price-chip (+ estimated)
- **AC-1.1** A crop with a **live** product price (resolved by crop slug OR `crops.hebrew_name = products.hebrew_name`)
  renders the chip as today: `בשוק <₪price>/<unit>`. (Built — see §4.1; route test exists.)
- **AC-1.2** A crop with **no** live product price **but** a `payload.market_link.price_current > 0` renders an
  **estimated** chip: distinct label **`מחיר מוערך`** (NOT `בשוק`), e.g. `מחיר מוערך ₪<price>/ק״ג`, visually
  differentiated (muted/dashed) so it reads as an estimate, not live.
- **AC-1.3** A crop with neither renders **no** chip (honest — never fabricated).
- **AC-1.4** Priority is strict: live price wins over the book estimate; estimate wins over nothing.
- **AC-1.5** Route tests: (a) live chip renders `בשוק` for a hebrew-name-linked product (exists); (b) estimate chip
  renders `מחיר מוערך` for a crop with `market_link.price_current` and no product; (c) no chip when neither.

### Item 2 — deep-provenance pills
- **AC-2.1** On `/crop-book/{slug}?depth=drill` (deep), a field whose value comes from a known source renders its
  EX/PR/WR provenance pill (`.pv-validated`/`.pv-unvalidated` etc.), including when the value originates from the
  **variety payload** (not only the enrichment mirror) — `source_class` resolved from the payload as a fallback.
- **AC-2.2** When there is genuinely no provenance, the source row is omitted (honest — no empty/blank pill, no
  fabricated source).
- **AC-2.3** The stale `winning_source_class` fallback comment in `CropBookViewController` is corrected to match
  behavior.
- **AC-2.4** A render/route test asserts a deep-depth crop with payload-only provenance shows the pill.

### Item 3 — calc precision-to-mockup
- **AC-3.1** `/calc/` matches `mockups/calc.html` at desktop + 375px (qa_probe `overflow=false` + visual parity):
  the question-builder (`.qb-goal` grid, step badges), goal set, area/time-anchor inputs, and result shapes align
  to the mockup's spacing/typography/labels.
- **AC-3.2** The 6 working client-side calculators are unchanged in behavior; only presentation is aligned.
- **AC-3.3** The 8 "בקרוב" server-stub calcs remain clearly marked as upcoming (no fabricated math).
- **AC-3.4** The created interface uses the **existing** calc code/endpoints/macros (`AssumptionField`, `/calc`
  endpoints, the qb-* components) — no parallel re-implementation (team_00 directive).

## 4. File-level design

### 4.1 Price-chip (reference build — already on `feat/wp-cb-book-market-pricechip` @ ab71d9f)
- `app/Controllers/CropBookViewController.php::entry()` — the price map now resolves per crop by **slug OR
  hebrew_name** (one `IN(...)` query keyed by both, result keyed by crop slug). Adopt this commit as the baseline.
- **Extension (AC-1.2):** in `entry()`, also extract `payload.market_link.price_current` per crop; pass a second
  map (or a `price_kind` flag: `live` | `estimated`) to the template. In `book_entry.php` the `.cc__price` chip
  branches on `price_kind`: `live` → existing `בשוק …`; `estimated` → `מחיר מוערך …` with a muted/dashed variant
  (add a small CSS modifier in `redesign.css`, e.g. `.cc__price--est`).
- Honest: the estimate only renders when `market_link.price_current > 0`.

### 4.2 Deep-provenance (`CropBookViewController.php` ~610–760)
- `buildSourceClasses($cb1_fields)` + the variety-payload fallback (the `$cb1_payload`/`field_state` path around
  line 686): ensure `source_class` is resolved from the variety payload when the enrichment mirror's
  `winning_source_class` is empty, so the template's source row renders. Fix the stale comment (~743).
- Template `crop_topics.php` / the deep `.prov`/`.srcline` rows: unchanged contract; they already render when a
  `source_class` is present.

### 4.3 Calc precision (`templates/pages/calc_dash.php` + `redesign.css` `.qb-*` rules)
- Diff `/calc/` vs `mockups/calc.html` at 375 + desktop; align spacing/type/labels in `calc_dash.php` + the
  `.qb-goal`/`.qb-intro`/`.step__h` rules in `redesign.css`. Reuse the existing components; do not rebuild the engine.
