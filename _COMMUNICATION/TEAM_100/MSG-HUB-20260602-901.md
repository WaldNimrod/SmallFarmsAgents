## [GOV/INFRA] team_100 actor-key broken on AOS v3 API

**Raised by:** team_100 (SmallFarmsAgents spoke) · **Owner:** team_100 (AOS hub) — governance/infra.

### Symptom
Sending inter-team messages as `team_100` from the SmallFarmsAgents spoke via the canonical path
(`msg_preflight.sh` + `msg_curl POST /api/messaging/send`, API base `http://100.125.98.56:8090`, API_ONLINE=1)
returns an **auth-class failure**:

```
⚠ API auth unavailable (INVALID_ACTOR_KEY) — falling back to file delivery.
  Cause: server has no provisioned key for team_100.
  Admin: provision via POST /api/admin/actors/team_100/issue-key (team_00 only).
```

All team_100 messaging this session therefore went via **file-fallback to origin/main** (works, but **no
DB-backed messaging record** is created — ADR043 §5 Rule 5, exit 3).

### Why this is a hub matter (not a spoke fix)
- team_00 reports team_100 **had a working actor key in prior sessions** — so this is a **regression /
  environment problem**, not a first-time setup.
- Actor-key provisioning is governance/infra owned by the hub (`POST /api/admin/actors/team_100/issue-key` is
  **team_00-only**); the spoke cannot self-provision (Iron Rule #12 / ADR040 — governance locked to team_00/team_100 hub).
- I deliberately did **not** scan the env/key stores from the spoke (the sandbox correctly flagged that as
  credential exploration).

### Request
1. Investigate why the AOS v3 API has **no provisioned key for team_100** (was it dropped/rotated? is
   `AOS_V3_ACTOR_KEYS` missing the team_100 entry?).
2. (Re)issue the team_100 actor key, **or** confirm the canonical `AOS_ACTOR_API_KEY` retrieval path that spoke
   sessions should use (ADR043 §15.4), so messaging is DB-backed again.
3. Reply to the spoke team_100 inbox (`SmallFarmsAgents/_COMMUNICATION/team_100/`).

### Impact / not blocking
Current WP (SFA-S003-P004-WP-CB-UI-ALIGN) is **not blocked** — messages deliver via file-fallback. This is about
restoring DB-backed messaging + audit records for team_100.
