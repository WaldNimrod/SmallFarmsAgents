# REGISTER — SFA-S003-P004-WP-CB-DATA-API — incremental, validated, code-preserved data API

**Date:** 2026-06-12 · **By:** team_100 (team_00 directive) · **Status:** REGISTER · **LOD:** REGISTER · **Effort:** LARGE
**Strategic.** Foundation that all future crop-data work depends on.

## Why (team_00, 2026-06-12)
`seed --all` is a **full rebuild** of the crop dataset from source files. team_00 ruling: the dataset has outgrown
full re-seeding — it is now too complex, and every full re-seed is "guaranteed damage" (it has minted duplicate
crops, re-emitted forbidden AC-05 derived fields, and caused the recurring 70-vs-77 production drift). **No more
`seed --all` for ongoing work.** All gaps must be filled **incrementally**, with validation, and the canonical data
must be preserved in code.

## What exists today (the starting point)
- **Incremental push already works:** `organic_market_agent/publisher/sfa_ingest_push.py --crop-ids` pushes specific
  crops over the HMAC `POST /api/v1/ingest` API with an idempotency key + an `_AGRONOMY_FIELD_WHITELIST` (the AC-05 /
  license firewall) + `ingest_log`. This is the "add a few crops without touching the rest" path.
- **AC-05 enforcement is after-the-fact:** the forbidden-derived-field ban is enforced by a *post-seed strip*
  (`canon.migrate phase4`), not a pre-write gate.

## The gap to close (this WP)
1. **Pre-write validation layer** — field types / enum values / required fields / the AC-05 derived-field prohibition,
   enforced *before* any write (local upsert AND ingest push), so bad data can never be written rather than stripped later.
2. **Code-preserved canonical data** — the canonical crop dataset reconstructable from git (versioned data files +
   importers as the build, not the DB as the only SSoT), so the Postgres SSoT can be rebuilt deterministically
   *without* re-running the dangerous full seed.
3. **Incremental upsert API/CLI** — a first-class, validated "enrich crop X field Y" operation (single crop / field
   set), replacing `seed --all` for all maintenance.
4. **Retire / fence `seed --all`** — guard it behind an explicit flag + make AC-05 a hard-fail at write time.

## Notes
- Backend/pipeline only (Python + the ingest endpoint); no delivery-tier UI.
- **Blocks** the data-currency + cropdata-dates work (they must flow through this, not a re-seed).
- Derived from the WP-CB-SRC-SWEEP closure findings + team_00's 2026-06-12 directive.
